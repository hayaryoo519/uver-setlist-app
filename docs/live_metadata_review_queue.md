# 管理一覧の追加情報レビュー導線（Issue #109）

状態：管理者専用一覧API、管理一覧の件数/理由表示・絞り込み、追加情報への通知リンクを実装。
使い捨てPostgreSQL 18で030/031と実API SQL・同時更新を検証済み（[DB検証](./live_metadata_db_verification.md)）。合成APIでPC/モバイルの[実ブラウザ検証](./live_metadata_browser_verification.md)も完了。実Staging適用と実Web Push確認は未実施。

## 管理者専用API

GET /api/lives/metadata-review

既存authorize/adminCheckを適用する。公演と追加情報をLEFT JOINし、未保存公演も含めて1クエリで取得する。
原文/取得元スナップショットは取り出さず、管理用classification.noteもDB側で除く。
公演名称・既存の公開特記事項は旧公演のタグフォールバック判定だけに使い、以下の応答には含めない。

```json
[
  {
    "liveId": 42,
    "revision": 3,
    "unconfirmedFields": ["country", "participants"],
    "hasUnconfirmed": true,
    "countryConflict": "unresolved",
    "needsClassificationReview": false
  }
]
```

- 原文・候補値・管理メモ・履歴・管理者IDは応答に含めない。
- 公開一覧/詳細にレビュー情報は追加しない。
- 取得失敗は500とし、空配列や0件に偽装しない。
- 読取専用でrevisionや履歴を変更しない。
- 新しいマイグレーションは追加しない（保存層には既存の030/031が必要）。

## 未確認の判定

全項目が未確認である通常公演を「生誕祭対象や対バン相手も確認する必要がある」とは扱わない。
有効タグを使い、以下の適用項目を判定する。

| フィールド | 未確認として数える条件 |
|---|---|
| country | 全公演。開催国が手動確定されていない |
| members | 有効タグにbirthdayがあり、対象メンバーを手動確認していない |
| participants | 有効タグにvsがあり、共演者を手動確認していない |

国コード候補が取得できたことは手動確認ではない。
メンバー/共演者の「なしと確認済み」は未確認に数えない。
タグを手動除外して適用対象でなくなった場合は、その項目の確認を要求しない。
旧公演の名称/特記事項フォールバックと、保存済みtags=[]を尊重する処理は公開側と共通化した。
日付・会場だけから生誕祭や開催国を埋めない。

これは**適用する構造化情報の未確認**であり、公演全体のレビュー完了認定ではない。
全タグ/原文/セトリを人が確認したという状態、確認した候補revisionの記録はまだ設けない。

## 取得元不一致と分類検討

countryConflict:
- none：国候補の不一致なし。
- unresolved：取得元で複数の国候補があり、開催国未確定。
- confirmed：国候補は不一致だが開催国は手動確定済み。

国を確定しても取得元の証拠は消さない。「confirmed」は今の手動設定があるという意味で、新候補すべてをレビュー済みと認定する意味ではない。
needsClassificationReviewは既存のclassification.needsReviewから独立して判定する。

## 管理一覧

公演一覧にレビュー状態の列と「追加情報レビュー」のフィルターを追加。

- すべて
- 未確認
- 取得元不一致（未確定・確定済みの両方）
- 開催国未確定の不一致
- 分類検討

件数は年度・文字・セトリ条件で絞る前の取得済み公演集合について表示する。
フィルターは既存の年度・文字・セトリ条件とAND。
「属性」から従来の追加情報モーダルを開き、未確認項目や取得元・メモを確認して修正する。
複数条件に該当する公演は各件数に入るため、各件数の合計は総公演数とは一致しない。

- 読込中/エラー時は件数を「—」とし、レビュー条件による絞り込みを利用できない。全公演表示へは戻せる。
- エラー後の前回キャッシュを、正常なレビュー結果として表示しない。
- 片方の一覧だけ更新されて公演IDのレビュー情報が未取得なら、未取得の件数/行表示を出す。未確認等の件数に勝手に含めず、確認済みとも表示しない。
- 公演/追加情報の保存・削除後にレビューキャッシュも無効化する。最新情報はタブ再入場/ウィンドウフォーカス/更新ボタンでも取得する。
- 取得要求は取り消し可能。管理者IDごとにキャッシュを分け、非管理者への権限変更でも以前の結果を返さない。
- 絞り込み等で非表示になった公演の一括削除選択を解除する。

## 通知・URL

管理者向け新公演通知（notifyNewLive）のリンク：

`/admin?tab=lives&metadata=42`

公式スケジュール取り込みの新規公演通知のリンク：

`/admin?tab=lives&review=unconfirmed`

未確認のキューは今回追加分に限定したものではなく既存公演も含む。日付順・年度条件と合わせて確認する。
新しい通知送信条件や、既存公演の候補変更だけで通知する処理は追加しない。
取り込み失敗等の別種の運用通知は従来のリンクを維持する。

review値：all/unconfirmed/conflict/unresolved/classification。
metadataは正の整数公演ID（PostgreSQL intの範囲）。不正な値では開かない。

- 単件リンクは一覧の絞り込み条件で見えない公演も、読込済み公演集合から開ける。
- 対象が見つからない場合は削除/未取得の可能性を表示し、一覧更新を案内する。
- 同じマウント中はリンクを一度だけ消費し、保存/データ再取得で閉じたモーダルを再び開かない。
- 編集中に別リンクへ変わっても現在の入力を上書きせず、現在のモーダルを閉じてから新しい対象を開く。
- 管理者以外はページ/API双方の既存認可により利用できない。
