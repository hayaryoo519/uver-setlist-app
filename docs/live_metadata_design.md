現行の `docs/live_semantic_filters.md` は試作の実装説明であり、本設計の完成状態を示さない。
取得経路の現状と追加後の確認・修正タイミングは [自動追加後の確認フロー](./live_metadata_review_workflow.md) を参照。

## 目的

正式名称や自由記述を保持しながら、固定した属性・対象メンバー・開催国・共演者でライブを検索する。
表記ゆれや属性の組み合わせからタグを自動作成しない。

## 情報の役割

| 情報 | 役割 |
|---|---|
| title / tour_name | 正式な公演名称。タグ判定の都合で書き換えない |
| special_note | 既存の任意入力欄「Special Note (Optional)」。公演固有の補足として維持 |
| 固定タグ | 検索用の共通分類。表示ラベルとは別に固定IDを持つ |
| 対象メンバー | 生誕祭の対象。メンバーの固定IDを使う |
| 開催国 | ISO 3166-1 alpha-2。海外属性の判定元 |
| 共演者 | アーティストの固定IDと出演上の役割を持つ |
| 確認状態・出典 | 未確認と確認済みを区別し、自動取得と手動確定を管理 |

同じ情報を特記事項と専用項目の両方に入力することは必須にしない。
特記事項から候補を抽出できるが、専用項目の変更時に特記事項を自動で書き換えない。

## 固定タグ

| 分類 | ID | 表示名 | 主な判定元 |
|---|---|---|---|
| 企画 | mens | 男祭り | 正式名称、特記事項、管理者確認 |
| 企画 | womens | 女祭り | 同上 |
| 記念・季節 | birthday | 生誕祭 | 同上。日付だけでは判定しない |
| 記念・季節 | christmas | クリスマス | 名称、特記事項。12月公演だけでは判定しない |
| 記念・季節 | anniversary | 周年記念 | 名称、特記事項。周年数・結成/デビュー等を推測しない |
| 共演形式 | vs | 対バン | 公演の説明、対バン相手の確認情報 |
| 開催地域 | overseas | 海外公演 | 確認済み開催国がJP以外 |

- アコースティックは具体的な公演実績・検索需要を確認できていないため、試作から除去済み。
- フェスは既存の `FESTIVAL` 種別で検索する。別の編集可能なフェスタグを持たない。
- ファンクラブ限定などは実際の公演名称・条件を確認してから追加を判断する。
- タグ追加は管理画面の自由入力ではなく、定義・判定語・テストの変更で行う。
- 同じ分類内はOR、分類間および他の検索条件とはAND。分類ラベル・配置はUI実装時に確定する。

「海外生誕祭」「TAKUYA∞ Birthday」のような複合タグは作らない。
生誕祭タグ＋対象メンバー、海外公演属性＋開催国という独立した条件で検索する。

## 対象メンバーと開催国

対象メンバーは複数指定可能。生誕祭と判断できても対象が分からなければ未確認のままにする。
名称の別表記はメンバー辞書の別名に集約し、タグを増やさない。

開催国は会場・外部サービスの国コードを取得候補にする。
会場名の英語表記、ツアー名、タイムゾーンだけから国や海外公演を確定しない。
国が不明なら国内とも海外ともみなさない。国内/海外の検索からは除外し、「開催国未確認」で探せるようにする。

## 共演アーティスト

アーティストごとに固定ID、正式表示名、検索用別名を持つ。
公演との関連には次の役割を記録する。

| 役割 | 意味 |
|---|---|
| co_headliner | 対バン相手 |
| guest | ゲスト出演 |
| supporting_act | オープニング/サポート出演 |

役割の分類は入力例を確認してから拡張する。同一公演・同一アーティスト・同一役割の重複を禁止する。
同じアーティストでも異なる役割は保持できる。

- `EVENT` 種別だけで対バンとみなさない。
- 対バンタグが付いていても、相手を特定できなければ未確認にする。
- フェスの全出演者をUVERworldの対バン相手として登録しない。
- ゲスト参加だけでは対バンタグを付けない。
- 記号をすべて落とす等の強い正規化でアーティストを自動統合しない。
- 外部IDの一致は同一性の判断材料とする。名前・別名の一致は候補提示とし、曖昧な場合は管理者が選択する。
- 辞書にない相手は管理者がアーティストを登録する。取得処理が無制限に辞書を増やさない。

既存タグに収まらない企画は、正式名称・特記事項を残し文字検索可能にする。
管理情報として「分類検討」とメモ・出典を記録し、通常公演のタグなしや情報不足と区別する。
判定語の不足は既存辞書で吸収し、新しい分類は実例・検索需要を確認して定義を追加する。

検索は「共演アーティスト」と任意の役割指定を組み合わせる。
例：アーティストAの共演全般／アーティストAが対バン相手の公演のみ。

## 未確認と「なし」

対象メンバー、開催国、共演者は個別に確認状態を持つ。

- 未確認＋空：情報が取れなかった、まだ確認していない。
- 未確認＋値：自動取得した候補。確定情報ではない。
- 確認済み＋値：管理者が確定した情報。
- 確認済み＋空：対象なしと確認した情報。対象メンバー・共演者で使用する。

開催国は「対象なし」がないため、確認済みには有効な国コードを必須とする。
空配列やnullだけでは確認状態を推測しない。

## 取得・編集・再取得

1. 外部の名称・説明・会場・国などを取得し、固定辞書で属性候補を生成する。
2. 出典、取得日時、判定ルールのバージョンを候補に記録する。
3. 管理画面で候補と未確認箇所を表示する。
4. 管理者はタグ追加/除外、対象メンバー、開催国、共演者と役割を確定する。
5. 公開画面と検索は同一の有効情報を利用する。

候補と手動確定を分離する。再取得は候補のみ更新し、手動確定を上書きしない。
未編集のタグは自動判定を利用できる。管理者が除外したタグは再判定で復活させない。
各項目に「自動候補に戻す」を設け、戻した場合のみ最新候補を採用する。
手動確定された共演者一覧への自動追記もしない。

海外属性は有効な開催国から導出し、タグだけを独立して編集しない。
対バン相手が確認済みで存在すれば対バンとして扱う。タグ除外との矛盾があれば保存前に解消を求める。
生誕祭タグなしで対象メンバーが入力されている場合も、黙って保存せず関連情報の修正を求める。

共演者等の未確認候補は検索上の確定情報として使わず、管理画面で候補として表示する。
自動判定タグの利用と構造化情報の確認状態は区別する。

## 保存・API構成案

最終DDLは実装時に検討する。以下は責務の分離案。

- ライブ属性：自動候補タグ、手動追加/除外タグ、判定元・ルール版。
- ライブ追加情報：開催国、対象メンバー、項目別確認状態、手動確定/自動候補の区別。
- アーティスト辞書：正式名、別名、必要に応じて外部ID。
- ライブ共演者：公演ID、アーティストID、役割、確認状態・出典。

一覧・詳細APIで同じ有効タグ/追加情報を返す。管理用APIでは候補・手動設定・出典も返す。
編集APIは項目省略を「変更なし」とし、明示的なクリア/自動候補への復帰と区別する。
旧クライアントの更新で新しい追加情報を消さない。
管理用の更新は既存の管理者認可を適用する。

スキーマ変更は新しい連番マイグレーションのみで追加する。
既存データは原則未確認で移行し、日付だけで生誕祭や会場名だけで開催国を埋めない。
旧コード・新コードで動作する後方互換性を維持する。本番DBへの直接操作は行わない。

## 実装順序

1. 実在する公演例と既存データで、タグ判定語・共演者の役割を検証する。
2. 固定タグと追加情報の型、候補/手動確定/有効情報を決める。
3. 後方互換なマイグレーション・一覧/詳細/編集APIとテストを追加する。
4. 管理画面に候補確認・編集・自動候補への復帰を追加する。
5. 収集経路に国コード・出典の受け渡しを追加し、再取得で手動設定を保護する。
6. 一覧/詳細の表示・検索を有効情報に統一する。
7. 試作のフロント生成と不要なタグを整理する。

## 主な受け入れ条件

- Xmas/Christmas/クリスマスは同じタグになる。未知の表記から新しいタグは生まれない。
- メンバー名・アーティスト別名が違っても、確認後は同一IDで検索できる。
- 海外/国内/国未確認を区別できる。
- 対バン相手、ゲスト、フェス出演者を混同しない。
- 未確認と確認済みの「なし」を区別できる。
- 再取得・判定辞書更新で手動追加/除外・共演者・開催国が上書きされない。
- 自動候補への復帰で最新候補が反映される。
- 既存クライアントからの更新で新しい項目が消えない。
- 一覧と詳細のタグ・追加情報が一致する。
