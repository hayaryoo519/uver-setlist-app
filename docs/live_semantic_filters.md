# ライブ属性フィルター（Issue #109）

> 全体設計は [ライブ属性・追加情報の設計案](./live_metadata_design.md)、公開契約は [公開表示・検索](./live_metadata_public.md) を参照。アコースティックは除去済み。[共演者の辞書・編集・検索](./live_collaborators.md)も接続済み。

ライブ一覧で、自動候補に手動追加/除外を適用した属性を検索できる。
保存には `033_live_metadata.sql`、共演者には `034_live_artists.sql` のマイグレーションが必要。使い捨てPostgreSQLで検証済み（[DB検証](./live_metadata_db_verification.md)）。既存のStaging/本番DBへの適用は未実施。

## 生成タイミング

取り込み時にサーバーで候補を生成・保存し、公開APIで有効タグを計算する。
`useLives` / `useLiveDetail` と `normalizeLive` はAPIのタグを優先し、明示的な空タグを再生成しない。
旧API/集計データにtagsがない場合のみ、フロントの固定辞書へフォールバックする。画面のフィルター操作では再判定しない。

## 分類

| 分類 | 属性 | 主な判定語 |
|---|---|---|
| イベント属性 | 男祭り / 女祭り | 男祭り・男祭・男性限定 / 女祭り・女祭・女性限定 |
| ライブ形式 | 対バン | 対バン、対ばん、VS |
| 記念日・季節 | 生誕祭 | 生誕祭、誕生祭、BIRTHDAY、BIRTH DAY |
| 記念日・季節 | クリスマス | クリスマス、Xmas、X'mas、X’mas、Christmas |
| 記念日・季節 | 周年記念 | 周年、ANNIVERSARY |
| 開催地域 | 海外公演 | 確認済み開催国がJP以外。名称から推測しない |

判定語の共通辞書は `server/utils/liveTagRules.json`、検索判定の分類定義は `src/utils/liveText.ts` を参照。
画面は検索分類と独立した「公演の特徴・共演・開催地」の3グループで表示する（[表示整理](./live_filter_layout.md)）。
フェスはタグと重複させず、既存の `FESTIVAL` 種別で検索する。

## 検索ルール

- 同じ分類内の選択はOR。例：男祭り＋女祭り → どちらかの属性を持つ公演。
- 異なる分類間の選択はAND。例：男祭り＋生誕祭 → 両方の属性を持つ公演。
- 年度・文字検索・既存ライブ種別・楽曲・確認済み開催国・対象メンバー条件と併用可能。
- 開催地の一般向けUIは「日本」「海外」の2ボタン。未選択は全公演で、選択中の再押下で解除する。国不明は日本・海外のどちらにも含めない。
- 国別・開催国未確認を新規に指定するUIは設けない。以前の保存済み条件の検索・チップ表示・解除は維持する。
- PCではヘッダー、モバイルでは絞り込みパネルに表示する。
- 選択した属性は件数バッジと解除可能なチップに反映される。
- 他の既存フィルターと同様にルーターのstateに保持する。URL共有で属性条件は引き継がない。

## 判定の制約

Unicode NFKCと大小文字を正規化する。英語の単語境界を保持し、Manifestなどの部分文字列をフェスとして扱わない。
複数フィールドの境界をまたいだ単語は作らない。
日付・会場・出演者だけから属性を推測しない（メンバーの誕生日と同じ日でも生誕祭とは限らない）。
名称に判定語がない公演や、辞書にないフェス名には属性が付かない場合がある。
判定語の追加は陽性・誤検出のテストをセットで行う。
