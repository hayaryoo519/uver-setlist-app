# 本番ログインが失敗する（自前認証・RLS関連）

`https://kakeibo.haya-ryooo.net` への初回デプロイ後、ログインが通らなかった件。
原因が複数重なっていたため、切り分けの順序ごとに記録する。

## 症状

ログイン時に以下が順に発生した。

1. `rows: 0` — ユーザーが見つからない（HTTP 401）
2. `function current_account_status() does not exist`（HTTP 500）
3. `query would be affected by row-level security policy for table "user_account_controls"`
4. argon2 検証が `verified: false`（HTTP 401）

## 原因

### 1. `.env.local` が `.env` を上書きしていた

Next.js では `.env.local` が `.env` より優先される。
`.env.local` に古い `DATABASE_APP_URL`（ポート 5433 の Docker、誤ったパスワード）が
残っており、本番 DB ではなく別 DB を見ていたため `rows: 0` になった。

### 2. migration 023 の SECURITY DEFINER 関数が作成されていなかった

migration 023 は `admin_roles` / `user_account_controls` に
`FORCE ROW LEVEL SECURITY` を設定した後、`LANGUAGE sql` の
`SECURITY DEFINER` 関数（`active_admin_role` / `current_account_status`）を作成する。

PostgreSQL は SQL 関数を CREATE する際にクエリを検証するが、
`FORCE RLS` が設定されたテーブルへのアクセスは、テーブルオーナーであっても
`BYPASSRLS` 権限がない限り突破できない。`SET row_security = off` でも回避不可。

`kakeibo` ユーザーは DB オーナーだが真のスーパーユーザーでも BYPASSRLS でもないため、
これら 2 関数だけ作成に失敗していた（`admin_lookup_users` 等の plpgsql 関数は作成成功）。

### 3. ログイン前に app_users / auth_credentials を読めなかった

RLS ポリシーが `id = app_current_user_id()` 前提だったため、
未ログイン状態（`app.current_user_id` 未設定）ではユーザー検索ができなかった。

### 4. 保存済みパスワードハッシュが想定パスワードと不一致

`auth_credentials` に保存されていた argon2 ハッシュが想定パスワードで検証できなかった
（前段の作成時に別パスワードが使われた可能性）。argon2 自体は正常動作していた。

## 解決手順

1. **`.env.local` を削除**し、本番 `.env` の接続情報だけを使うようにした。
   - `.env` の `DATABASE_URL` パスワードの末尾誤記（余分な記号）も修正した。
2. **migration 035** を追加して、`admin_roles` / `user_account_controls` の
   `FORCE RLS` を外し（`alter table ... no force row level security`）、
   `active_admin_role` と `current_account_status` を作り直した。
   - kakeibo_app からの直接アクセスは通常の RLS で引き続き保護される。
3. **migration 034** を追加して、`app.current_user_id` 未設定時に
   `app_users` / `auth_credentials` を SELECT できる RLS ポリシーを足した。
4. **パスワードハッシュを再生成して UPDATE**。
   ```bash
   node -e "require('argon2').hash('<新パスワード>', { type: 2 }).then(console.log)"
   # 出力ハッシュで auth_credentials を UPDATE（RLS を一時 DISABLE して実行）
   ```
5. `npm run build` → `pm2 restart kakeibo` → ログイン成功（HTTP 200）。

## 再発防止

- **`.env.local` を本番サーバーに置かない。** Next.js では `.env.local` が `.env` を
  上書きするため、本番では混乱の元。デプロイ時に存在チェックする。
- **FORCE RLS テーブルへ SQL/SECURITY DEFINER 関数を定義する際は、
  そのテーブルの FORCE RLS を外すか、ロールに BYPASSRLS を付与する。**
  migration 023 の関数群は 035 で再作成済み。新規セットアップでは
  001 → 004〜035 を順に流せば再現する。
- 初期管理者作成は `scripts/create-user.mjs` を使い、
  作成直後に実際の email/password でログインできるか必ず確認する。
- 関連: アプリ側手順は `kakeibo/Docs/operations/initial-setup.md` に記載。
