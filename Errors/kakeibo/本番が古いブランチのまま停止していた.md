# 本番が古いブランチのまま停止していた（手動デプロイ未実施）

`https://kakeibo.haya-ryooo.net` のログイン画面が旧UIのまま、
オンボーディングの「世帯を作成して次へ」が動かなかった件。

## 症状

1. ログイン画面が古いデザイン（`auth-page--branded` / パスワードトグル なし）
2. オンボーディングでボタンを押しても何も起こらない（画面遷移なし、エラーなし）
3. pm2 エラーログに `function current_account_status() does not exist`

## 原因

### 1. 本番アプリが `docs/ux-tracking-refresh` ブランチで止まっていた

`/home/haya-ryoo/apps/kakeibo` の `git branch` が `main` ではなく
`docs/ux-tracking-refresh` を向いていた。
`main` の最新コミットから 11 コミット分の機能・修正が本番に届いていなかった。

CD が未実装のため手動でデプロイする必要があったが、その手順が実施されていなかった。

### 2. `current_account_status()` エラーは旧ビルドの残骸

migration 035 で修正済みの関数が、旧ビルドのキャッシュされた `.next` から
呼ばれていたためエラーログに残っていた。新ビルドでは発生しない。

### 3. `app_users` が空に見えた（誤診）

`kakeibo`（DB オーナー）ロールで SELECT しても `FORCE ROW LEVEL SECURITY` が
有効なため、`kakeibo` ロール向けのポリシーがなく全行が非表示になっていた。
実際にはアカウントは存在していた。
→ 確認する場合は RLS を一時 DISABLE してから SELECT すること。

## 解決手順

```bash
cd /home/haya-ryoo/apps/kakeibo

# 1. main に切り替えて最新を取得
git fetch origin
git checkout main
git pull origin main

# 2. 依存を入れ直してビルド
npm ci
npm run build

# 3. 再起動
pm2 restart kakeibo
```

ビルド時に `npm ci --omit=dev` はビルドツールが落ちてコンパイル失敗する。
本番でも `npm ci`（フル）でビルドすること。

## 再発防止

- **CD を実装する。** `cicd.md` の Step 6 のワークフローを実装し、
  `v*` タグプッシュで自動デプロイされる状態にする。
  手動デプロイは忘れる・分岐が残る・ブランチを間違えるリスクがある。
- **デプロイ前後に `git branch` と `git log --oneline -3` で本番ブランチを確認する。**
- **DB を `kakeibo` ロールで直接 SELECT する際は RLS を一時 DISABLE してから確認する。**
  `FORCE ROW LEVEL SECURITY` のテーブルはオーナーロールでも全行非表示になる。

## デプロイ後に発覚した追加バグ

デプロイ後、オンボーディングで「世帯を作成できませんでした。」が出た。

**原因**: `create_current_user_household`（migration 017）が `app_users` 等に
アクセスする際、FORCE RLS に弾かれ 42501 エラー（035/036 と同じ問題）。

**対象テーブル**: `app_users` / `households` / `household_members` /
`payment_sources` / `categories` / `household_invitations`

**修正**: migration 044 で FORCE RLS を解除。本番 DB に直接適用済み。
