# リリース後に本番が 404 になった（ビルド未実施）

`https://kakeibo.haya-ryooo.net` を開いたら「404 - This page could not be found.」が表示された件。

## 症状

1. `https://kakeibo.haya-ryooo.net/` を開くと Next.js の 404 ページが表示される
2. `pm2 list` では kakeibo プロセスは `online`（起動済み）
3. `pm2 logs kakeibo` のエラーログに `ERR_HTTP_HEADERS_SENT` が連続出力されていた
4. `curl http://localhost:3100/` も 404 を返す（Nginx 通過後でも同じ）

## 原因

### 本番の `.next` ビルドが古いまま、サーバーが再起動されていた

`/home/haya-ryoo/apps/kakeibo` は最新コード（v0.10.0 / main 最新）に `git pull` されていたが、
**`npm run build` を実行せず** pm2 が再起動されていた。

その結果、古い `.next` ビルドが読み込まれ、ルート `/` のビルド成果物が存在しない状態で
サーバーが起動していた。

ルート `/` は動的ページ（`ƒ`）であり、ビルドしないと `.next/server/app/page.js` が
新しいコードで再生成されない。

### `ERR_HTTP_HEADERS_SENT` はエラーの結果であって原因ではない

`/` が 404 になると Next.js の `_not-found` ルートが呼ばれ、
その内部でヘッダー二重送信が起きていたためログに出ていた。

## 解決手順

```bash
cd /home/haya-ryoo/apps/kakeibo

# 1. ビルドを実行（必須）
npm run build

# 2. pm2 を再起動
pm2 restart kakeibo

# 3. 動作確認（307 リダイレクト = 正常）
curl -o /dev/null -w "%{http_code}" http://localhost:3100/
```

## 確認ポイント

ビルド出力の `Route (app)` テーブルに `ƒ /` が含まれていれば正常にビルドされている。

```
Route (app)                               Size  First Load JS
┌ ƒ /                                   38.7 kB        145 kB   ← これが必要
├ ○ /_not-found                           998 B        103 kB
...
```

## 再発防止

- **リリース後は必ず** `git pull → npm run build → pm2 restart` の順で実施する
- `pm2 restart` だけでは古いビルドが残る。コード変更があれば必ずビルドし直すこと
- CD（GitHub Actions 自動デプロイ）が未実装のため手動運用が続く限りこのリスクは残る
  → `cicd.md` の Step 6 ワークフロー実装が根本対策
